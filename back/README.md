# 🏀 Платформа для бронирования баскетбольных игр (Backend)

RESTful API бэкенд для управления баскетбольными играми, бронированиями (слотами игроков и ожидающих), базой пользователей и автоматизацией платежей. Проект работает на актуальной версии **Node.js v20**.

## Обзор и Технологический стек

- **Язык/Платформа:** Node.js (v20)
- **Фреймворк:** Express.js
- **База данных:** SQLite3 (без использования сложных ORM, запросы пишутся на чистом SQL)
- **Тестирование:** Jest (v27), Supertest
- **Логирование:** Winston (с ротацией файлов логов)
- **Интеграции:** Telegram Bot API (webhook), Twilio (SMS), Платежные прокси-серверы

## Архитектура и структура проекта

Проект построен на **многослойной архитектуре (Layered Architecture)**, что обеспечивает четкое разделение ответственности:

1.  **Точка входа (`server.js` & `app.js`)**:
    - `app.js` отвечает исключительно за инициализацию Express приложения, подключение middleware (body-parser, cookie-parser, rate limiters) и регистрацию маршрутов API. **Важно:** Порт никогда не биндится внутри `app.js`, чтобы избежать ошибок `EADDRINUSE` во время работы Jest-тестов.
    - `server.js` импортирует настроенное приложение, запускает HTTP-сервер на заданном порту и инициализирует фоновые задачи (cron-интервалы).
    
2.  **API Layer (`api/`)**:
    - Содержит обработчики маршрутов Express (контроллеры).
    - Разделен по логическим сущностям (например: `game.js`, `user.js`, `payment.js`).
    - Извлекает параметры из запросов (`req.body`, `req.query`), вызывает методы DAL слоя и возвращает стандартизированные JSON-ответы.

3.  **Data Access Layer (DAL) (`dal/`)**:
    - Инкапсулирует всю работу с базой данных SQLite3.
    - В контроллерах доступен глобально через `req.dal`. Запрещено делать прямое `require('../dal/dal')` внутри Express-маршрутов для сохранения mockability в тестах.
    - Использует параметризованные SQL-запросы (`?`) для предотвращения SQL-инъекций. Избегайте конкатенации строк в SQL-запросах.
    - Содержит бизнес-сущности и модели в `types.js` (`Game`, `Reservation`, `User`).

4.  **Connectors (`connector/`)**:
    - Модули для общения с внешним миром: Telegram Bot, Twilio SMS, платежные шлюзы.

5.  **Utilities (`utils/`)**:
    - `logger.js`: Настроенный логгер Winston.
    - `notifications.js`: Ядро событийной архитектуры проекта (Event Emitter).

## Бизнес-логика и Событийная модель

Система интенсивно использует **событийно-ориентированный подход (Event-Driven)** через `utils/notifications.js`.

Это позволяет диспетчеризировать тяжелые задачи (например, отправку SMS или Telegram сообщений) вне HTTP-цикла обработки запроса.
1. При изменении критического состояния (создана игра, произведена оплата, пользователь забанен), вы всегда должны убедиться, что вызывается `events.emit('event.name', payload)`.
2. Подписчики асинхронно реагируют на эти события для уведомления ботов/админов без задержки ответа клиенту. (Полный список поддерживаемых событий можно найти в `tests/utils.notifications.test.js`).

## Подходы, соглашения и Code Style

- **Модульная система:** Мы используем CommonJS (`require()` и `module.exports`). Не используйте синтаксис ES6 `import/export`.
- **Порядок импортов:** 
  1. Встроенные Node-модули (`fs`, `path`).
  2. Внешние NPM пакеты (`express`, `uuid`).
  3. Внутренние модули проекта (`./utils/misc`).
- **Язык и Форматирование:** Чистый JavaScript (не TypeScript). Отступы — 2 пробела. Используйте одинарные кавычки (`'`) для строк (за исключением шаблонных строк `` ` ``).
- **Асинхронный код:** Предпочитайте `async/await` цепочкам `.then().catch()`. Всегда используйте `await` для операций БД перед переходом к следующему шагу.
- **Логирование:** Не используйте `console.log()`. Внутри Express роутов используйте `req.log.info()`, `req.log.error()`. Вне роутов инициализируйте локальный логгер: `const log = require('../utils/logger').create('MODULE_NAME');`.
- **Обработка ошибок:** Ловите асинхронные ошибки внутри контроллеров и возвращайте стандартизированный ответ (`{ error: true, reason: 'message' }`). Никогда не утекайте стектрейсы или сырые ошибки БД (SQLITE_ERROR) клиентам.

## Тестирование

Тесты **крайне важны** для этого проекта. При внесении изменений вы должны убедиться, что тесты успешно проходят. Тесты запускаются in-memory и не должны мутировать реальную файловую базу данных.

**Запуск полного тест-сьюта (с покрытием):**
```bash
BASKET_MODE=dev npm test
# или
BASKET_MODE=dev npx jest tests --coverage --forceExit
```

**Запуск одного тестового файла (быстро):**
```bash
BASKET_MODE=dev npx jest tests/api/game.test.js
```

**Правила тестирования:**
- При тестировании контроллеров API (`api/`), полностью мокайте DAL: `jest.mock('../../dal/dal')`. Это изолирует бизнес-логику от базы данных.
- При тестировании самого DAL (`dal/`), мокайте нативный драйвер SQLite3: `jest.mock('sqlite3')`, чтобы возвращать требуемые JSON-структуры для покрытия ветвей кода.

## Локальная разработка и запуск

Проект зависит от переменной окружения `BASKET_MODE`, которая контролирует загружаемые настройки (из `config/settings.json`). Локальная разработка всегда должна проходить в режиме `dev`.

1. **Установка зависимостей:**
   ```bash
   npm install
   ```
2. **Запуск сервера для разработки:**
   ```bash
   BASKET_MODE=dev npm start
   # или
   BASKET_MODE=dev node server.js
   ```

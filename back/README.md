# 🏀 Платформа для бронирования баскетбольных игр (Backend)

RESTful API бэкенд для управления баскетбольными играми, бронированиями (слотами игроков и ожидающих), базой пользователей и автоматизацией платежей. Проект изначально был написан для Node.js v12 и успешно обновлен для работы на актуальной версии **Node.js v20**.

## 🛠 Технологический стек

- **Язык/Платформа:** Node.js (v20)
- **Фреймворк:** Express.js
- **База данных:** SQLite3 (без использования сложных ORM, запросы пишутся на чистом SQL)
- **Тестирование:** Jest, Supertest
- **Логирование:** Winston (с ротацией файлов логов)
- **Интеграции:** Telegram Bot API (webhook), Twilio (SMS), Платежные прокси-серверы

## 🏗 Архитектура проекта

Проект построен на **многослойной архитектуре (Layered Architecture)**, что обеспечивает четкое разделение ответственности между маршрутизацией, бизнес-логикой и доступом к данным.

### Основные компоненты системы:

1.  **Точка входа (`server.js` & `app.js`)**:
    - `app.js` отвечает исключительно за инициализацию Express приложения, подключение middleware (body-parser, cookie-parser, rate limiters) и регистрацию маршрутов API.
    - `server.js` импортирует настроенное приложение, запускает HTTP-сервер на заданном порту и инициализирует фоновые задачи (cron-интервалы).
    
2.  **API Layer (`api/`)**:
    - Содержит обработчики маршрутов Express (контроллеры).
    - Разделен по логическим сущностям: `game.js`, `games.js`, `reservation.js`, `user.js`, `payment.js`.
    - Извлекает параметры из запросов (`req.body`, `req.query`), вызывает методы DAL слоя и возвращает стандартизированные JSON-ответы.

3.  **Data Access Layer (DAL) (`dal/`)**:
    - Инкапсулирует всю работу с базой данных SQLite3.
    - В контроллерах доступен через `req.dal` (глобально прокидывается через middleware).
    - Содержит бизнес-сущности и модели в `types.js` (`Game`, `Reservation`, `User`).
    - Использует параметризованные SQL-запросы для предотвращения SQL-инъекций.

4.  **Connectors (`connector/`)**:
    - Модули для общения с внешним миром.
    - `telegram.js`: Обработка Webhook-событий от Telegram, отправка сервисных сообщений, рассылка уведомлений администраторам и участникам.
    - Управление внешними API (оплаты, SMS-шлюзы и т.д.).

5.  **Utilities (`utils/`)**:
    - `auth.js`: Логика аутентификации (генерация и парсинг cookie-токенов с использованием `crypto`).
    - `logger.js`: Настроенный логгер Winston для различных модулей (выводит логи в консоль для dev-режима и в файлы для prod-режима).
    - `misc.js`: Вспомогательные функции (работа с датами, форматирование времени).
    - `notifications.js`: Ядро событийной архитектуры проекта (Event Emitter).

## 🚀 Бизнес-логика и Событийная модель (Event-Driven)

Приложение активно использует событийную модель (Event Emitter) для асинхронной обработки побочных эффектов. Это позволяет не блокировать основной HTTP-запрос при выполнении тяжелых или сетевых задач (например, отправке SMS или Telegram-уведомлений).

**Как это работает:**
1. Пользователь бронирует место на игру (API `reservation.js`).
2. DAL обновляет записи в БД и делает коммит транзакции.
3. Система генерирует внутреннее событие, например: `events.emit('reservation.created', payload)`.
4. Подписчики в `utils/notifications.js` перехватывают событие и отправляют уведомление в Telegram (через `connector/telegram.js`) или списывают кредиты.

## ⚙️ Конфигурация и запуск среды

Приложение крайне зависимо от переменной окружения `BASKET_MODE`, которая определяет, какой блок настроек из `config/settings.json` будет загружен (`dev` или `prod`).

### Установка зависимостей:
```bash
npm install
```

### Запуск сервера для локальной разработки:
Запуск в режиме разработчика (используется БД `basket.dev.db`):
```bash
BASKET_MODE=dev npm start
# или
BASKET_MODE=dev node server.js
```

### Запуск тестов:
Проект покрыт unit- и интеграционными тестами. В тестах DAL мокается для изоляции бизнес-логики маршрутов, а сама БД изолируется.

**Запустить все тесты с отчетом о покрытии:**
```bash
BASKET_MODE=dev npm test
```

**Запустить конкретный тестовый файл:**
```bash
BASKET_MODE=dev npx jest tests/api/game.test.js
```

## 🔐 Аутентификация и Безопасность

- **Авторизация:** Происходит на основе подписанных cookies (в `utils/auth.js` используется модуль `crypto` для симметричного шифрования ID пользователя с солью).
- **Rate Limiting:** Для предотвращения спама и брутфорса используется `express-rate-limit` (защита эндпоинтов отправки SMS/Telegram-кодов подтверждения).
- **Скрытие ошибок:** В production-режиме стектрейсы и детали SQL-ошибок никогда не отдаются клиенту (возвращаются стандартизированные объекты `{ error: true, reason: '...' }`). Критические сбои логируются локально и отправляются администраторам в Telegram.

## 📝 Стандарты кодирования (Code Style)

- Модульная система: **CommonJS** (`require` / `module.exports`).
- Отступы: **2 пробела**.
- Предпочтительно использование `async / await` вместо цепочек `.then()`.
- Именование переменных: `camelCase` для функций и переменных, `PascalCase` для моделей/классов, `UPPER_SNAKE_CASE` для констант.
- Строки в JavaScript: одинарные кавычки (`'`), кроме шаблонных строк (`` ` ``).
